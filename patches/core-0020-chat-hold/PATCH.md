# core-0020-chat-hold: hold a chat's agent stopped while its folder moves (R-130, November 15th, 2026)

`POST /api/conversations/{id}/runtime/hold` with `{ "hold": true|false, "stop": bool }`. Holding ends the chat's agent process (kill and wait, as a runtime restart does) and the task manager builds no task for it until it is released, so a send, its team or a schedule cannot start it in a folder that is being moved (Windows refuses to move a folder a process runs in). A chat working on a turn is refused with a `WORKING:` conflict (409) unless `stop` is set, which ends the turn as the Stop button does. Released, it starts again as usual from its row, which by then names the new folder. Held state lives in memory: an AionCore restart releases everything.

Files: `aionui-ai-agent/src/task_manager.rs` (trait `set_held`/`is_held` with defaults, `WorkerTaskManagerImpl.held`, refused in `get_or_build_task`, test `held_conversation_is_not_built_until_released`), `aionui-conversation/src/service.rs` (`hold_runtime`), `aionui-conversation/src/routes.rs` (the route).
